# WiFi Fix — hAP ax3 5 GHz (2026-04-26)

## Problem

`wifi1` / 5 GHz on the MikroTik hAP ax3 appeared broken:

- wifi1 was detected and bound to hardware but was not reliably usable after SSID/config changes
- 5 GHz SSID initially would not accept the expected password
- 2.4 GHz / wifi2 was working throughout

The radio itself was not dead — proved when `wifi1` successfully broadcast `T5-OPEN` and accepted a 5 GHz client.

## Root cause

The issue was not DFS, country, bridge, DHCP, NAT, or dead hardware.

The key finding:

- wifi1 **failed** when relying on the shared security profile/passphrase path
- wifi1 **worked** when the passphrase and security settings were applied directly to wifi1

Practical cause: bad/inconsistent WiFi security/profile state on `wifi1`, caused by earlier API-driven changes including blank SSID and inactive-state manipulation.

## Resolution steps

1. Confirmed both radios existed and wifi1 hardware was bound
2. Confirmed wifi1 could run and broadcast
3. Set wifi1 SSID back to T5
4. Set country=New Zealand on wifi1
5. Tested open 5 GHz WiFi to prove the radio/client path worked
6. Applied security directly to wifi1 instead of relying on the shared profile
7. Confirmed T5 connected successfully using WPA2 first, then WPA2/WPA3
8. Set wifi1 channel back to auto with skip-dfs-channels=10min-cac
9. Set country=New Zealand on wifi2 as well
10. Verified both radios running, bridged to bridgeLocal, issuing DHCP, providing internet

## Cleanup

| Action | Detail |
|--------|--------|
| Renamed security profile | `t5_wpa2_test` → `t5_secure` |
| Removed unused config object | `t5` |
| Renamed shared base config | `home` → `wifi_base` |

## Final state

**wifi1 / T5 (5 GHz)**
- Band: 5ghz-ax, 20/40/80MHz, auto channel, skip-dfs=10min-cac
- Country: New Zealand
- Security: WPA2-PSK + WPA3-PSK, passphrase applied directly on wifi1
- FT: disabled
- Bridge: bridgeLocal ✅

**wifi2 / T2 (2.4 GHz)**
- Band: 2ghz-ax, 20/40MHz, auto channel
- Country: New Zealand
- Security: WPA2-PSK + WPA3-PSK
- FT: enabled
- Bridge: bridgeLocal ✅

## Note

wifi1 passphrase and security are set **directly on the interface**, not inherited from the shared profile. Do not consolidate into a shared profile until wifi1 has survived a reboot and normal client reconnects.
