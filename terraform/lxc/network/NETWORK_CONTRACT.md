# Network Contract — terraform/lxc/network

## What this module owns

Network intent for each Proxmox environment. Each file (`pve-test.yaml`, `pve.yaml`)
is the single canonical source for:

- Zone definitions (name, VLAN ID, subnet, gateway)
- Physical attachment config (bridge, SDN VNet)
- Cross-zone firewall policies (enforced at MikroTik)

`network/<env>.yaml` does **not** decide which stack is attached to which zone.
Actual stack-to-zone membership is declared in each stack's `stack.yaml` via
`network.zone`.

The platform layer reads these files to drive SDN VNet creation and LXC network
attachment. Firewall rule generation also reads the `policies` section.

## What it may read from elsewhere

Nothing. `network/<env>.yaml` is a pure declaration. It does not import from other
files.

## What may depend on this module

- `terraform/lxc/main.tf` — reads attachment config and policy rules
- `terraform/lxc/ansible/playbooks/configure-network-sdn-vnet.yml` — reads zone
  definitions to create SDN zones (note: currently handles Simple zones only; VLAN
  zones must be created manually — see code gap below)
- AI context: hand this file to any AI session that needs to understand zone
  placement, IP ranges, or firewall policy

## Authority

- Zone definition authority: `network/<env>.yaml`
- Stack placement authority: `stacks/<stack>/stack.yaml` via `network.zone`
- Attachment and policy consumer: `terraform/lxc/main.tf`

All policies are enforced at the MikroTik firewall, not at the Proxmox VNet
firewall. The VNet firewall (`firewall: true` in `mgmt_seg` and `edge_seg`) controls
inbound per-container rules only. Cross-zone ACCEPT rules are never generated by
the current main.tf (known bug — see Observations.md Phase 04 note 1).

## What must not be edited casually

- **Zone VLAN IDs** — changing a VLAN ID requires reconfiguring the MikroTik trunk
  port and recreating the SDN VNet. All containers in the zone lose connectivity
  during the change.
- **Subnet / gateway values** — every container in a zone has its IP and gateway
  hardcoded in its `stack.yaml`. Changing the subnet requires updating all affected
  `stack.yaml` files and re-running Terraform.
- **`snat: false`** — must remain false on all zones. Setting it true causes
  double-NAT (MikroTik also SNATs at WAN) and breaks LAN → container ingress.
- **Zone names** — used as keys in `stack.yaml` (`network.zone`). Renaming a zone
  requires updating every `stack.yaml` that references it.

## Code gap: VLAN zone provisioning

`configure-network-sdn-vnet.yml` currently handles Simple zone creation only.
VLAN zones must be created manually via `pvesh`:

```sh
pvesh create /cluster/sdn/zones --type vlan --zone <zone> --bridge vmbr0 --nodes pve-test
pvesh create /cluster/sdn/vnets --vnet <vnet> --zone <zone> --tag <vlan_id>
pvesh create /cluster/sdn/vnets/<vnet>/subnets --subnet <cidr> --gateway <gw> --type subnet
pvesh set /cluster/sdn
```

Fixing this playbook to support `zone_type: vlan` is a candidate improvement for
Phase 07 or a standalone task.
