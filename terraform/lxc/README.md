# terraform/lxc — Data-Driven LXC Deployment Pipeline

Provisions Proxmox LXC containers with Docker, optionally deploying application stacks via Portainer. Each stack is defined by a single YAML file; Terraform handles the full lifecycle from container creation through Ansible provisioning to destroy-time cleanup.

## Architecture

```
┌─────────────┐     ┌──────────────┐     ┌──────────────────┐     ┌───────────┐
│ stack.yaml  │────▶│  Terraform   │────▶│  Ansible roles   │────▶│ Portainer │
│ (per-stack) │     │  (LXC + inv) │     │  (provision)     │     │ API       │
└─────────────┘     └──────────────┘     └──────────────────┘     └───────────┘
```

**Flow:** stack.yaml → Terraform creates LXC → generates inventory → runs Ansible playbook → Ansible installs Docker, starts Portainer Agent, registers endpoint, deploys compose stack via Portainer API.

**Destroy flow:** Terraform triggers cleanup.yml → Ansible deletes Portainer stacks and endpoint → Terraform destroys LXC container.

## Directory Structure

```
terraform/lxc/
├── main.tf                          # Root module: reads stacks, creates LXC, runs Ansible
├── variables.tf                     # Input variables (Proxmox creds, defaults)
├── outputs.tf                       # Stack outputs (hostname, IP, container ID)
├── terraform.tfvars                 # Local credentials (gitignored)
├── templates/
│   └── inventory.tpl                # Ansible inventory template
├── modules/
│   └── lxc-docker-host/             # Reusable module: single LXC container
│       ├── main.tf                  #   Container resource with Docker mount
│       ├── variables.tf             #   Module inputs (cores, memory, IP, etc.)
│       └── outputs.tf               #   Outputs (container_id, hostname, ip)
├── stacks/                          # Stack definitions (one directory per stack)
│   ├── test-docker/
│   │   ├── stack.yaml               #   LXC + deployment config
│   │   ├── docker-compose.yml       #   Compose file for app stack
│   │   └── inventory.yml            #   Generated by Terraform (gitignored)
│   ├── test-lxc/
│   │   ├── stack.yaml               #   Bare LXC, no app stack
│   │   └── inventory.yml            #   Generated (gitignored)
│   └── .hold/                       #   Future stacks (not yet active)
│       ├── management/stack.yaml
│       ├── media/stack.yaml
│       ├── minecraft/stack.yaml
│       └── torrent/stack.yaml
└── ansible/
    ├── ansible.cfg                  # Ansible config (roles_path, defaults)
    ├── playbooks/
    │   ├── deploy-stack.yml         # Full lifecycle: docker + agent + API + stack
    │   ├── docker-base.yml          # Standalone Docker setup (no Portainer)
    │   └── cleanup.yml              # Destroy-time: remove stacks + endpoint
    └── roles/
        ├── docker_base/             # Ensure Docker running, install SDK, registry mirror
        ├── portainer_agent/         # Deploy Portainer Agent via compose + systemd
        ├── portainer_api/           # Register endpoint with central Portainer (idempotent)
        └── app_stack/               # Deploy/update compose stack via Portainer API
```

## How to Add a New Stack

1. Create a directory under `stacks/`:

```bash
mkdir stacks/my-app
```

2. Create `stacks/my-app/stack.yaml` with LXC and deployment config:

```yaml
# Required
hostname: my-app
ip_address: "192.168.1.60/24"

# Optional (shown with defaults)
vmid: 140                    # Auto-assigned if omitted
cores: 2
memory: 2048
swap: 512
rootfs_size: 8
docker_storage_size: "20G"
ostemplate: "storage-template:vztmpl/debian-13.1-2-docker-template.tar.gz"
target_node: pve
gateway: "192.168.1.1"

# Deployment — omit all of these for a bare Docker LXC (like test-lxc)
ansible_playbook: "deploy-stack"   # Playbook name (without .yml)
portainer_agent: true              # Enables destroy-time cleanup
app_stack_name: "my-app"           # Stack name in Portainer
```

3. If using `ansible_playbook: "deploy-stack"`, create `stacks/my-app/docker-compose.yml`:

```yaml
services:
  my-service:
    image: my-image:latest
    ports:
      - "8080:8080"
    restart: unless-stopped
```

4. Apply:

```bash
terraform apply
```

Terraform will create the LXC, generate inventory, and run the Ansible playbook automatically.

## Stack YAML Reference

| Field | Required | Default | Description |
|---|---|---|---|
| `hostname` | Yes | — | Container hostname and Portainer endpoint name |
| `ip_address` | Yes | — | Static IP in CIDR notation (e.g., `192.168.1.60/24`) |
| `vmid` | No | Auto | Proxmox VM ID |
| `cores` | No | `2` | CPU cores |
| `memory` | No | `2048` | Memory in MB |
| `swap` | No | `512` | Swap in MB |
| `rootfs_size` | No | `8` | Root filesystem size in GB |
| `docker_storage_size` | No | `20G` | Docker data mount size |
| `ostemplate` | No | `local:vztmpl/debian-docker-template.tar.gz` | LXC template |
| `target_node` | No | `pve` | Proxmox node |
| `gateway` | No | `192.168.1.1` | Network gateway |
| `ansible_playbook` | No | — | Playbook to run after creation (omit for bare LXC) |
| `portainer_agent` | No | `false` | Enable Portainer cleanup on destroy |
| `app_stack_name` | No | Stack directory name | Name for the stack in Portainer |
| `portainer_server_ip` | No | `192.168.1.4` | Central Portainer server IP |
| `tags` | No | `[<stack_name>]` | Proxmox tags |

## Ansible Roles

### docker_base
Validates Docker is running, installs the Python Docker SDK (`docker`), and optionally configures a registry mirror via `/etc/docker/daemon.json`. Controlled by `docker_base_configure_mirror` (default: `false`).

### portainer_agent
Creates `/opt/portainer/docker-compose.yml` with the Portainer Agent service, validates it with `docker compose config`, manages it via a systemd unit, and waits for the agent HTTPS ping on port 9001. Uses self-signed certs internally (`validate_certs: false`).

### portainer_api
Authenticates with the central Portainer server, checks if an endpoint with the same name already exists (idempotent), and registers a new agent endpoint if needed. All API calls delegate to localhost.

### app_stack
Deploys a Docker Compose stack via the Portainer API. Checks for an existing stack on the target endpoint. If the stack exists, compares SHA256 hashes of the current and desired compose content — only updates if changed. Creates a new stack if none exists.

## Playbooks

| Playbook | Trigger | Runs on | What it does |
|---|---|---|---|
| `deploy-stack.yml` | `ansible_playbook: "deploy-stack"` | Target LXC | docker_base → portainer_agent → portainer_api → app_stack |
| `docker-base.yml` | `ansible_playbook: "docker-base"` | Target LXC | docker_base only (bare Docker, no Portainer) |
| `cleanup.yml` | Terraform destroy (automatic) | localhost | Deletes Portainer stacks + endpoint via API |

## Terraform Resources

For each stack, Terraform creates:

| Resource | Purpose |
|---|---|
| `module.lxc[<name>]` | Proxmox LXC container with Docker storage mount |
| `local_file.ansible_inventory[<name>]` | Generated inventory at `stacks/<name>/inventory.yml` |
| `null_resource.ansible_provision[<name>]` | Runs Ansible playbook (only if `ansible_playbook` is set) |
| `null_resource.stack_cleanup[<name>]` | Destroy-time cleanup (only if `portainer_agent: true`) |

## Prerequisites

- Proxmox VE with API token (`automation@pve!terraform`)
- LXC template with Docker pre-installed
- Central Portainer CE instance (for stacks using deploy-stack)
- SSH key pair for Ansible access to containers
- `terraform.tfvars` with credentials (see `variables.tf` for required values)

## Commands

```bash
# Initialise
terraform init

# Preview changes
terraform plan

# Apply all stacks
terraform apply

# Destroy a single stack
terraform destroy -target='module.lxc["test-docker"]' \
  -target='null_resource.ansible_provision["test-docker"]' \
  -target='null_resource.stack_cleanup["test-docker"]' \
  -target='local_file.ansible_inventory["test-docker"]'

# Destroy everything
terraform destroy
```

## Conventions

- Stack directory name = Terraform map key = Portainer endpoint name
- Generated files (`inventory.yml`) are gitignored — only `stack.yaml` and `docker-compose.yml` are committed
- Stacks in `.hold/` are not active — move them to `stacks/` to deploy
- All Ansible roles use the `<role_name>_` variable prefix per ansible-lint standards
- Internal connections use self-signed certificates (`validate_certs: false` is intentional)
