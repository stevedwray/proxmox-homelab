# Runtime Matrix Checkpoint — 2026-07-16

All 16 cells of the runtime × backend × deployment matrix are now verified and
passing. This supersedes the 2026-07-15 checkpoint, whose "required next
steps" are now done.

- runtimes: llama.cpp and Ollama
- backends: Vulkan and ROCm/HIP
- deployments: host bare-metal, host + Docker, Incus bare, Incus + Docker
- every cell: `backend_verified: true`, backed by both a log-based device

## What changed since 2026-07-15

1. **Backend verification is no longer log-text-only.** In addition to
   requiring the runtime's own logs to name the physical device (rejecting
   `llvmpipe`, `library=cpu`, or a bare `library=rocm`/`vulkan` substring
   match), every cell now also samples real GPU utilization via `rocm-smi`
   throughout the stress test (`roles/*/files/gpu-cpu-sample.sh`, polled
   every 0.2s) and asserts it exceeded 5% somewhere in the window. This
   caught a live CPU fallback that the log-based check alone had missed.
2. **Root-caused and fixed the actual bug behind that CPU fallback:**
   Ollama's `OLLAMA_IGPU_ENABLE` override was only being set for the Vulkan
   backend, not ROCm - Strix Halo is an integrated GPU regardless of
   backend, so Ollama was dropping the ROCm device and silently falling
   back to CPU for every ROCm cell until this was fixed.
3. **Root-caused and fixed the Incus Vulkan Ollama `llvmpipe` fallback**
   flagged as unresolved in the previous checkpoint: `ollama_bench` hardcoded
   `GGML_VK_VISIBLE_DEVICES=1` for any Incus-targeted Vulkan cell, assuming a
   different device enumeration order inside the container. `vulkaninfo`
   confirmed device ordering is identical on the host and inside Incus
   (device 0 = physical RADV GPU, device 1 = llvmpipe) - the override was
   simply wrong and was forcing every Incus Vulkan cell onto the software
   renderer. Both `incus-bare` and `incus-docker` Vulkan cells are now
   confirmed on the real GPU.
4. **Fixed a `journalctl` history-bleed bug** in `llamacpp_server_bench`:
   the transient `llamacpp-server-bench` systemd unit's log history persists
   across repeated invocations under the same unit name, so a capture
   without `--since` could read a stale device_info line (or none) from a
   previous cell. Fixed by recording each cell's start time (with a 5s
   safety buffer against clock/journal granularity) and passing `--since`.
5. **Made per-cell failures non-fatal to the matrix.** Both roles now wrap
   their per-cell body in `block/rescue/always`: a failure (backend
   mismatch, low GPU utilization, install error) records that cell as
   failed (`backend_verified: false`, with an `error` field) and lets the
   loop continue to the next combination, rather than aborting the
   remaining cells. Cleanup still always runs via `always:`.
6. **Fixed the `systemctl set-environment` global env-var leak**: Ollama's
   backend-selection variables were being set at the systemd *manager*
   level (host-wide, not scoped to the `ollama` unit) and never unset,
   which had been silently breaking the normal, non-benchmark `llama-server`
   service between runs. `ollama_bench`'s `always:` block now runs the
   matching `systemctl unset-environment` after every bare-metal cell.

## Bugs hit and fixed while building the GPU-utilization gate

These are implementation details, not experiment findings, but worth
recording since they'd otherwise resurface identically:

- A YAML `>-` folded block scalar does not interpret backslash escapes, so
  `.split('\n')` inside one reached Jinja as the two literal characters
  `\` and `n`, silently failing to split anything. Switched to
  `.splitlines()`, which takes no separator argument and sidesteps the
  issue entirely.
- The sampler's own extraction command, `grep -o '[0-9]*$'`, anchored to
  end-of-line - but the JSON value is followed by a closing quote
  (`"0"`), so it always matched an empty string and silently defaulted to
  0. Fixed to `grep -o '[0-9]\+'` (unanchored).
- A single short single-shot request completes in well under a second,
  which is too brief for `rocm-smi`'s own refresh interval to reliably
  register - even at 0.2s sampling, a known-good GPU cell read 0%
  utilization for the single-shot phase. Utilization sampling was moved to
  wrap the multi-second concurrent stress test instead, where sampling
  reliability is far higher (50+ samples per cell).
