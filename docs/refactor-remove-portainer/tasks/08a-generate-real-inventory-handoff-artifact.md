# Task 08a: Generate real inventory handoff artifact for Task 09 preflight

## Type

Development

## Objective

Generate and verify one real Terraform-generated `inventory.yml` handoff artifact
for `terraform/lxc/stacks/harbor-stack/` so Task 09 can validate
`ansible_playbook` extraction against a live artifact that satisfies Decision 4.

This task is intentionally narrower than Task 09. It does not create
`scripts/provision.sh`, does not run platform orchestration, and is not the
final rebuild gate.

## Files

- `terraform/lxc/stacks/harbor-stack/inventory.yml` (generated by Terraform;
  do not handcraft)

## Preconditions

- Task 00 complete — `inventory.tpl` renders `ansible_playbook`.
- Task 07 complete — active stacks declare `deployment_tier`.
- Task 08 complete — Terraform no longer invokes Ansible for stack
  configuration.
- Task 08b complete — the legacy destroy-time `null_resource.stack_cleanup`
  Ansible cleanup path is retired from Terraform code/state in scope for
  `harbor-stack` validation.
- Runbook preflight returns `pve-test`.
- If `terraform/lxc/stacks/harbor-stack/inventory.yml` already exists, the
  executor must still prove Terraform provenance before treating this task as a
  no-op.

## Representative Stack

This task uses `harbor-stack` as the fixed representative stack.

Why this stack:

- Task 09 already uses `harbor-stack` as its validation target, so keeping the
  same stack avoids redefining the handoff contract between tasks.
- `terraform/lxc/stacks/harbor-stack/stack.yaml` declares both
  `ansible_playbook: "deploy-harbor-stack"` and `deployment_tier: platform`,
  which exercises the exact metadata Task 09 must consume.
- It is a normal platform stack rather than the special-case `portainer-stack`,
  so it tests the handoff contract without turning this task into platform
  bootstrap orchestration.

## Preflight

```bash
./with-secrets bash -c 'echo $TF_VAR_proxmox_node'
test -f terraform/lxc/stacks/harbor-stack/inventory.yml && echo exists || echo missing
```

Expected outcome:

- `TF_VAR_proxmox_node` is exactly `pve-test`.
- The artifact is either missing and needs to be generated, or present and must
  be proven to come from Terraform.

Stop condition:

- any target other than `pve-test`

## Source-only validation

```bash
grep -E "ansible_playbook|deployment_tier" terraform/lxc/stacks/harbor-stack/stack.yaml
grep -n 'filename = "${local.stack_dir}/inventory.yml"' terraform/lxc/main.tf
grep -n "resource \"null_resource\" \"stack_cleanup\"" terraform/lxc/main.tf
grep -n "when        = destroy" terraform/lxc/main.tf
grep -n "ansible-playbook -i localhost, playbooks/cleanup.yml" terraform/lxc/main.tf
./with-secrets bash -c 'cd terraform/lxc/stacks/harbor-stack && terragrunt plan'
```

Expected outcome:

- `harbor-stack` still declares `ansible_playbook` and `deployment_tier`.
- Terraform still manages `inventory.yml` through `local_file.ansible_inventory`.
- Source inspection confirms no remaining destroy-time `stack_cleanup` path that
  invokes Ansible cleanup playbooks.
- The Terragrunt plan stays within the representative `harbor-stack` boundary.

Acceptable scope for the plan:

- generation or update of `terraform/lxc/stacks/harbor-stack/inventory.yml`
- harbor-stack-only infrastructure changes required to make that artifact real

Unacceptable scope for the plan:

- anything that requires full platform orchestration or the final rebuild gate
- undocumented production targeting or non-`pve-test` behavior
- drift that would widen the task beyond the representative `harbor-stack`

Stop condition:

- if source inspection still shows destroy-time `stack_cleanup` Ansible cleanup,
  stop and return control to Task 08b rather than attempting apply

## Operations

1. Run the preflight and source-only validation first.
2. If `terraform/lxc/stacks/harbor-stack/inventory.yml` is absent, run the
   minimum live action needed to let Terraform generate the real handoff
   artifact:

   ```bash
   ./with-secrets bash -c 'cd terraform/lxc/stacks/harbor-stack && terragrunt apply'
   ```

3. If `terraform/lxc/stacks/harbor-stack/inventory.yml` already exists, treat
   the task as a no-op only after proving Terraform provenance with:

   ```bash
   ./with-secrets bash -c 'cd terraform/lxc/stacks/harbor-stack && terragrunt state show local_file.ansible_inventory'
   ```

4. Do not create `inventory.yml` manually.
5. Do not run `scripts/provision.sh` in this task.
6. Do not widen this task into full platform provisioning or the rebuild gate.

## Task-complete validation

```bash
test -f terraform/lxc/stacks/harbor-stack/inventory.yml && echo exists
grep 'ansible_playbook:' terraform/lxc/stacks/harbor-stack/inventory.yml
python3 -c "import yaml,sys; inv=yaml.safe_load(sys.stdin); grp=next(iter(inv['all']['children'].values())); host=next(iter(grp['hosts'].values())); print(host.get('ansible_playbook',''))" < terraform/lxc/stacks/harbor-stack/inventory.yml
./with-secrets bash -c 'cd terraform/lxc/stacks/harbor-stack && terragrunt state show local_file.ansible_inventory'
```

Expected outcome:

- `terraform/lxc/stacks/harbor-stack/inventory.yml` exists.
- The artifact contains `ansible_playbook:`.
- The Python3 extraction prints `deploy-harbor-stack`.
- `terragrunt state show local_file.ansible_inventory` proves the file is the
  Terraform-managed handoff artifact rather than a handcrafted file.

## No-op

If `terraform/lxc/stacks/harbor-stack/inventory.yml` already exists, the task
may complete as a no-op only when:

- preflight still targets `pve-test`
- `terragrunt state show local_file.ansible_inventory` proves Terraform manages
  the file
- task-complete validation still finds `ansible_playbook: deploy-harbor-stack`

## Stop Conditions

- Stop if `harbor-stack` no longer declares both `ansible_playbook` and
  `deployment_tier: platform`.
- Stop if `terraform/lxc/main.tf` still contains a destroy-time
  `null_resource.stack_cleanup` path that invokes
  `ansible-playbook -i localhost, playbooks/cleanup.yml`.
- Stop if `terragrunt plan` or `terragrunt apply` would require bootstrapping
  another stack, invoking Ansible, or widening into full platform orchestration.
- Stop if `terragrunt plan` or `terragrunt apply` reveals unrelated drift that
  exceeds the representative `harbor-stack` boundary.
- Stop if `inventory.yml` exists but `terragrunt state show
  local_file.ansible_inventory` cannot prove Terraform manages it.
- Stop if the live action completes but `inventory.yml` is still absent,
  `ansible_playbook` is missing, or the Python3 extraction does not return
  `deploy-harbor-stack`.
- Stop if the task would require undocumented production-targeting or non-
  `pve-test` behavior.

## Rollback

If the live action mutates `harbor-stack` and validation fails, stop and roll
back only within the `terraform/lxc/stacks/harbor-stack/` Terragrunt unit to
the previous known-good state. Do not hand-edit `inventory.yml`, do not proceed
into Task 09, and do not widen the rollback into broader platform changes.

If no live mutation is required and Terraform provenance plus artifact
validation succeed, the task is a no-op and no rollback is needed.

## Rebuild gate note

This task is not the rebuild gate. The final explicit destroy/apply/provision
sequence remains the runbook's rebuild gate after Tasks 09 and 10 are complete.
