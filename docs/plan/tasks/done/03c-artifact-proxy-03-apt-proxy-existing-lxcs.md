## Objective

ci-runner-01 has `/etc/apt/apt.conf.d/01proxy` pointing at `192.168.1.35:3142`, and subsequent `apt-get` calls on the runner hit the apt-cacher-ng cache (verified via the stats page hit count increasing).

## Scope

- Re-run `deploy-ci-runner.yml` against ci-runner-01 to apply the apt proxy config and `.terraformrc`
- Use `--tags apt-proxy` if available, else run the full playbook (idempotent)
- Verify cache hit on apt-cacher-ng stats page

## Out of Scope

- Applying the proxy to harbor-stack or netbox-stack LXCs (those will get it naturally on next redeploy via the base role change from task 03c-01)
- Merging the feature branch — this should happen after both 03c-01 and 03c-02 tasks are complete

## Inputs

- `terraform/lxc/ansible/playbooks/deploy-ci-runner.yml`
- ci-runner-01 IP: `10.57.0.63`

## Expected Outputs

- `/etc/apt/apt.conf.d/01proxy` created on ci-runner-01
- `/root/.terraformrc` created on ci-runner-01 (from task 03c-02 change)
- No file changes to commit (codified in tasks 03c-01 and 03c-02)

## Constraints and Conventions

- Runner registration token is auto-generated by the playbook — the runner will NOT be re-registered if it is already registered (idempotent registration check)
- If the `deploy-ci-runner.yml` playbook has apt proxy as a tagged task (`--tags apt-proxy`), use the tag to avoid the registration step
- Verify cache hit by running `apt-get update` on ci-runner-01 and checking the apt-cacher-ng stats page

## Acceptance Criteria

- [ ] `/etc/apt/apt.conf.d/01proxy` present on ci-runner-01 with content `Acquire::http::Proxy "http://192.168.1.35:3142";`
- [ ] `/root/.terraformrc` present on ci-runner-01 with filesystem_mirror config
- [ ] `curl http://192.168.1.35:3142/acng-report.html` shows increasing hit count after `apt-get update` on ci-runner-01
- [ ] Branch `feat/apt-cacher-terraform-mirror` merged to `dev/pve-test` and pushed
- [ ] Phase 03c acceptance criteria in `docs/plan/phase-03c-artifact-proxy.md` fully satisfied

## Observations

- The runner playbook needs to be executed from the Ansible directory with the generated Terragrunt inventory so `roles_path` and SSH settings resolve correctly.
- The existing-runner deregistration path can fail even after the proxy and mirror files are written, so reruns should confirm the config files before assuming the whole playbook failed.
- The apt-cacher stats page is easiest to verify via the counted report view, and a repeatable package download is a clearer hit signal than `apt-get update` alone.
